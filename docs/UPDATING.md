# Updating Hatari, zlib, EmuTOS and Circle

## Hatari

Hatari is a git submodule in `third_party/hatari`, from
`https://github.com/hatari/hatari.git` (the official mirror of
https://framagit.org/hatari/hatari). BMMacintosh follows its master branch
rather than a release: after 2.6.1 Hatari split its user interfaces out of
the emulation core (`src/sdl/` for SDL, `src/retro/` for its libretro core),
which is the seam BMMacintosh's front end fits into. It is used unmodified;
everything specific to BMMacintosh is in `src/port/`:

| File | What it has to do with Hatari |
|---|---|
| `src/port/hatari.mk` | The list of Hatari (and zlib) source files to compile, from Hatari's `CMakeLists.txt` files |
| `src/port/config.h` | Hatari's build options, which its CMake build writes from `cmake/config-cmake.h` |
| `src/port/compat/hatari_prefix.h` | Included before each Hatari file: headers some of Hatari's count on, and declarations newlib lacks |
| `src/port/platform.c` | The front end's main: `Main_Init()` with Hatari's command line options, the frame loop (`m68k_go()` / `m68k_run()`), `Main_ErrorExit()` and the dialogs Hatari calls (`DlgAlert_Query()`...) |
| `src/port/screen.c`, `audio.c`, `timing.c`, `keymap.c`, `gui_event.c`, `joy_ui.c`, `statusbar.c`, `microphone.c` | The same functions as Hatari's `src/retro/` files of the same names |
| `src/port/posix_extra.c` | `scandir()`, `utime()`, `access()`, `chmod()` for newlib |
| `src/port/menu.c` | Changes Hatari's settings (`ConfigureParams`) and applies them with `Change_CopyChangedParamsToConfiguration()`, as Hatari's SDL dialogs do |
| `src/port/osd.c` | Draws the menu with Hatari's font (`src/gui-sdl/font10x16.h`) |

The 68000-68060 CPU core's opcode handlers are generated by `build68k` and
`gencpu`, built for the computer doing the build (the Makefile, and
`tools/hostsim/Makefile`), as Hatari's own CMake build does.

To move to a newer Hatari:

1. Fetch and check out the new commit (or a release tag):

   ```
   cd third_party/hatari
   git fetch origin
   git checkout <commit>
   cd ../..
   ```

2. Compare the source lists in Hatari's `src/CMakeLists.txt`,
   `src/cpu/CMakeLists.txt`, `src/falcon/CMakeLists.txt` and
   `src/debug/CMakeLists.txt` with `src/port/hatari.mk`, and add or remove
   files. Compare `cmake/config-cmake.h` with `src/port/config.h`. Compare
   the functions in `src/retro/` (the front end closest to BMMacintosh's)
   with `src/port/`: new functions, changed signatures, new calls at start
   up in `retro_init()` and `retro_run()`.
3. Build and test on the PC first: `tools/hostsim/run_tests.sh`, and try
   some programs in the live simulator (`tools/hostsim/live.sh`). Then
   build the kernels (`./build_sdcard.sh`) and try them on a Pi.
4. Update the version in `docs/THIRD_PARTY.md`, and commit:

   ```
   git add third_party/hatari src/port docs/THIRD_PARTY.md
   git commit -m "Update Hatari to <version>"
   ```

## zlib

zlib is a submodule in `third_party/zlib`, at a release tag (`v1.3.2`).
Check out a newer tag, compare its source files with `ZLIB_SRCS` in
`src/port/hatari.mk`, and update the version in `docs/THIRD_PARTY.md` and
`sdcard/licenses/zlib.txt`.

## EmuTOS

`make_emutos.sh` downloads EmuTOS's 1024K release from SourceForge and
checks it against a pinned SHA-256. For a new release, change
`EMUTOS_VERSION` and `EMUTOS_SHA256` there (the SHA-256 of the new
`emutos-1024k-<version>.zip`), run the tests, and update the version in
`docs/THIRD_PARTY.md` and `docs/TOS.txt`.

## circle-stdlib (Circle and newlib)

circle-stdlib is a submodule in `third_party/circle-stdlib`, pinned to the
same revision BMC64 uses. `make_all.sh` applies the patches in `src/patches/`
to Circle before building:

- `circle_sysconfig_patch.diff` enables multi-core and the USB FIQ
- `circle_linux_bug_patch.diff` turns off `BUG_ON`, whose checks in Circle's
  Linux emulation (used by VCHIQ for display and sound) only allow core 0;
  the emulator calls them from core 1, as BMC64 does
- `circle_bolt_keyboard_patch.diff` adds Logitech Bolt keyboard support
  (from BMC64)

To update, move the submodule to a new circle-stdlib release, run
`git submodule update --init --recursive`, then `./build_sdcard.sh`. If a
patch no longer applies, update it from the matching BMC64 patch or by
hand. `src/fbl.cpp` and `src/vchiqsoundbasedevice.cpp` use Circle's VC4
addon and may need the same changes BMC64 makes when it updates Circle.
